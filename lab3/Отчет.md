# Лабораторная работа 3

## Базовые растровые алгоритмы

### Цель работы

Сравнить визуальное сходство результатов работы алгоритмов: цифровой дифференциальный анализатор (ЦДА), алгоритм Брезенхема для отрезка и алгоритм Брезенхема для окружности.

## Программа и запуск

Программа написана на Python с использованием Tkinter из стандартной библиотеки. Внешние пакеты не требуются.

Из каталога `lab3`:

```bash
python main.py
```

Для измерения производительности всех алгоритмов:

```bash
python main.py --benchmark
```

В верхней части окна выбираются алгоритм и целочисленные координаты. Для отрезка задаются `(x₀, y₀)` и `(x₁, y₁)`, для окружности — центр `(x₀, y₀)` и целочисленный радиус `R`. Кнопка «Построить» рисует пиксели на координатной сетке. Масштаб изменяется колёсиком мыши относительно указателя или кнопками «+» и «−»; кнопка «100%» возвращает исходный масштаб. Поддерживаемый масштаб — от 33% до 600%. Плоскость перемещается полосами прокрутки и перетаскиванием средней кнопкой мыши; Shift + колёсико перемещает её по горизонтали. Сетка и подписи перерисовываются для видимой области, подписи разрежаются при уменьшении масштаба, а при построении фигура центрируется в окне. Зелёным и красным отмечены начало и конец отрезка, синим — остальные пиксели. Некорректный ввод сопровождается сообщением об ошибке.

## Теоретические сведения

Растровое изображение состоит из дискретных пикселей, тогда как геометрический отрезок или окружность описываются непрерывными координатами. Растеризация выбирает конечный набор пикселей, наилучшим образом приближающий заданную фигуру. Для отрезка приращение числа пикселей пропорционально его максимальной проекции по осям, поэтому алгоритмы имеют линейную временную сложность.

### Пошаговый алгоритм

Пусть `dx = x₁ − x₀`, `dy = y₁ − y₀`, а `N = max(|dx|, |dy|)`. Для каждого целого `i` от `0` до `N` вычисляются координаты точки:

```text
xᵢ = x₀ + i · dx / N
yᵢ = y₀ + i · dy / N
```

Обе координаты округляются до ближайших целых пиксельных координат. Если `N = 0`, отрезок вырожден и состоит из единственного пикселя. Прямое вычисление каждой точки требует деления и округления; в приложении половинные значения округляются от нуля.

### Цифровой дифференциальный анализатор (ЦДА)

ЦДА использует то же число шагов `N`, но вместо независимого вычисления координат хранит текущую точку и приращения:

```text
Δx = dx / N
Δy = dy / N
x ← x + Δx
y ← y + Δy
```

На каждом шаге текущие координаты округляются и выводятся на экран. Такой вариант сокращает объём вычислений по сравнению с повторным вычислением формулы прямой, но использует вещественную арифметику, которая может накапливать погрешность.

### Алгоритм Брезенхема для отрезка

Алгоритм Брезенхема выбирает следующий пиксель по целочисленной ошибке между идеальной линией и уже построенной растровой линией. Для положительного наклона в первом октанте распространённая запись использует `dx`, `dy` и начальную ошибку `e = 2dy − dx`; если `e ≥ 0`, выбирается диагональный пиксель и ошибка уменьшается на `2dx`, иначе выбирается следующий горизонтальный пиксель и к ошибке прибавляется `2dy`.

В программе применяется симметричная целочисленная форма, работающая во всех октантах и в обоих направлениях:

```text
dx = |x₁ − x₀|, dy = −|y₁ − y₀|
e = dx + dy
e₂ = 2e
если e₂ ≥ dy: e ← e + dy; x ← x + шагₓ
если e₂ ≤ dx: e ← e + dx; y ← y + шагᵧ
```

Обе проверки выполняются на каждой итерации. Это позволяет алгоритму обрабатывать прямые с любым наклоном, в том числе горизонтальные, вертикальные и вырожденные.

### Алгоритм Брезенхема для окружности

Окружность обладает восьмикратной симметрией: достаточно вычислить точки одного октанта, а остальные получить перестановкой координат и изменением их знаков. Для центра в начале координат уравнение окружности имеет вид `x² + y² = R²`. Алгоритм начинает с `(x, y) = (0, R)` и использует целочисленный параметр решения `d = 3 − 2R`. Если `d < 0`, следующая точка остаётся на прежнем уровне `y`; иначе `y` уменьшается на единицу. Затем `x` увеличивается на единицу, пока `x ≤ y`. Каждая пара смещений переносится на заданный центр. Повторяющиеся симметричные точки удаляются, что существенно, например, при `R = 0` и на диагоналях.

## Целочисленная сетка и визуализация

Начало координат находится в центре области рисования. Целочисленной точке `(x, y)` соответствует центр клетки экрана:

```text
screen_x = origin_x + x · масштаб
screen_y = origin_y − y · масштаб
```

Единичные линии сетки проходят через центры соседних клеток; ось `Y` направлена вверх, поэтому экранная координата `y` меняет знак. Каждый найденный алгоритмом пиксель изображается квадратом внутри клетки, а не произвольной точкой между линиями сетки. Масштаб изменяет только размер клеток на экране и не меняет входные координаты или результат растеризации.

## Проверочный пример

Рассмотрим отрезок `(1, 1) → (8, 5)`. Здесь `dx = 7`, `dy = 4`, `N = 7`. В пошаговом алгоритме и ЦДА `Δx = 1`, `Δy = 4/7`. Последовательность округлённых точек:

| `i` | Неокруглённая точка | Пиксель |
|---:|---:|---:|
| 0 | `(1; 1)` | `(1; 1)` |
| 1 | `(2; 1,571)` | `(2; 2)` |
| 2 | `(3; 2,143)` | `(3; 2)` |
| 3 | `(4; 2,714)` | `(4; 3)` |
| 4 | `(5; 3,286)` | `(5; 3)` |
| 5 | `(6; 3,857)` | `(6; 4)` |
| 6 | `(7; 4,429)` | `(7; 4)` |
| 7 | `(8; 5)` | `(8; 5)` |

Для целочисленного алгоритма Брезенхема в данном октанте `e₀ = 2dy − dx = 1`. При `e ≥ 0` выбирается диагональный пиксель и из ошибки вычитается `2dx = 14`, иначе выбирается горизонтальный пиксель и прибавляется `2dy = 8`. Последовательность ошибок перед выбором следующего пикселя: `1, −5, 3, −3, 5, −1, 7`. Получается та же последовательность пикселей, что и у пошагового алгоритма и ЦДА.

Для окружности с центром `(0, 0)` и радиусом `5` начальные значения — `x = 0`, `y = 5`, `d = 3 − 2·5 = −7`. До завершения первого октанта алгоритм получает пары `(0, 5)`, `(1, 5)`, `(2, 5)`, `(3, 4)` и отражает каждую пару относительно осей и диагоналей. Например, `(1, 5)` порождает `(±1, ±5)` и `(±5, ±1)`. Получившееся множество содержит 28 различных пикселей.

## Сложность и временные характеристики

| Алгоритм | Число шагов | Время | Дополнительная память результата |
|---|---:|---:|---:|
| Пошаговый отрезок | `N + 1`, где `N = max(|dx|, |dy|)` | `O(N)` | `O(N)` |
| ЦДА | `N + 1` | `O(N)` | `O(N)` |
| Брезенхем, отрезок | `N + 1` | `O(N)` | `O(N)` |
| Брезенхем, окружность | `O(R)` итераций, до 8 точек на итерацию | `O(R)` | `O(R)` |

В приложении время измеряется функцией `time.perf_counter_ns()` непосредственно вокруг вызова алгоритма; построение сетки, отрисовка Tkinter и обновление интерфейса в этот интервал не входят. Для воспроизводимого сравнения режим `--benchmark` измеряет по 500 вызовов на серию, выполняет пять серий и выводит медиану среднего времени одного вызова. Тестовые данные: отрезок `(0, 0) → (1000, 600)` и окружность радиуса `700`. Измерения зависят от компьютера, версии Python и фоновой нагрузки:

| Алгоритм | Среднее время вызова, мс |
|---|---:|
| Пошаговый, отрезок `(0, 0) → (1000, 600)` | 0,243887 |
| ЦДА, тот же отрезок | 0,164989 |
| Брезенхем, тот же отрезок | 0,106734 |
| Брезенхем, окружность `R = 700` | 0,807986 |

В измерениях этой реализации (Windows, Python 3.12.10) Брезенхем оказался быстрее двух вещественных вариантов на выбранном отрезке; пошаговый метод затратил около 2,28 раза больше времени, чем Брезенхем, а ЦДА — около 1,55 раза. Для окружности непосредственно сравнивать время с отрезком некорректно: входные данные и число точек различаются. Результаты являются характеристикой одного запуска и зависят от компьютера, версии Python и фоновой нагрузки. Для повторного замера на другом компьютере используйте `python main.py --benchmark`. Различие между алгоритмами не меняет порядок роста: пошаговый метод выполняет вычисления с вещественными числами и округлением, ЦДА накапливает дробные приращения, а Брезенхем использует целочисленные сравнения и сложения. Для окружности число обработанных симметричных позиций пропорционально радиусу, а не площади круга.
