# Архитектура приложения COLOR//STUDIO 2000

## 1. Назначение

Приложение позволяет задавать и редактировать один цвет сразу в трёх цветовых моделях, выбранных для нечётного варианта лабораторной работы:

- **CMYK** — голубой, пурпурный, жёлтый и чёрный;
- **RGB** — красный, зелёный и синий;
- **HLS** — оттенок, светлота и насыщенность.

Пользователь может менять параметры ползунками, вводить их в поля или выбрать цвет в стандартном диалоге. Приложение пересчитывает представления цвета и обновляет образец и HEX-код.

Исходный код находится в [main.py](./main.py). Преобразования цветовых моделей реализованы собственными формулами: `colorsys` и сторонние библиотеки для этих вычислений не применяются. Tkinter используется только для интерфейса и стандартного диалога выбора цвета.

## 2. Структура программы

Программа состоит из трёх частей:

1. **Константы интерфейса и описание моделей.** Цвета оформления задаются в начале файла. Словарь `MODELS` перечисляет каналы цветовых моделей и верхние пределы ползунков.
2. **Функции преобразования.** Четыре независимые функции переводят CMYK и HLS в RGB и обратно.
3. **Класс `ColorStudio`.** Создаёт окно, хранит текущее состояние цвета, связывает элементы интерфейса с преобразованиями и синхронизирует отображение.

Функция `main()` создаёт главное окно Tkinter, экземпляр `ColorStudio` и запускает цикл обработки событий.

### 2.1. Функции преобразований

| Функция | Назначение |
|---|---|
| `cmyk_to_rgb(values)` | Преобразует CMYK в RGB |
| `rgb_to_cmyk(rgb)` | Преобразует RGB в CMYK |
| `hls_to_rgb(values)` | Преобразует HLS в RGB |
| `rgb_to_hls(rgb)` | Преобразует RGB в HLS |

RGB выбран внутренним представлением текущего цвета. Поэтому значения из CMYK и HLS сначала переводятся в RGB, а затем из этого общего представления вычисляются остальные модели. Это позволяет обойтись без отдельных цепочек преобразований, например CMYK → HLS.

### 2.2. Состояние интерфейса

Экземпляр `ColorStudio` хранит:

- `rgb` — текущий цвет как кортеж из трёх целых компонентов RGB в диапазоне 0–255;
- `entries` — переменные Tkinter, связанные с полями ввода каждой модели;
- `scales` — переменные ползунков каждой модели;
- `updating` — флаг блокировки реакции на программное обновление ползунков.

Также хранятся ссылки на виджеты образца цвета, HEX-кода и строки состояния, чтобы обновлять их при изменении цвета.

## 3. Организация окна

В конструкторе `ColorStudio.__init__` создаётся главное окно с тёмным фоном. В верхней части находятся название и подпись проекта. Центральная область содержит три одинаково построенные панели, а внизу располагаются:

- прямоугольный образец выбранного цвета;
- HEX-код в формате `#RRGGBB`;
- строка состояния.

Панели создаются в цикле по элементам `MODELS`. Метод `_build_model_panel(parent, model, column)` строит интерфейс одной модели: заголовок, строку на каждый канал, поле ввода, ползунок и кнопку выбора цвета. Максимальный диапазон каждого ползунка берётся из `MODELS`.

## 4. Сценарии взаимодействия

### 4.1. Ручной ввод

Поле принимает число. Нажатие Enter или потеря полем фокуса запускает `apply_entry(model)`.

1. `_values_from_entries(model)` читает значения каналов.
2. Каждое значение разбирается как число и проверяется на конечность и соответствие допустимому диапазону.
3. Для RGB дополнительно проверяется, что значение целое.
4. При ошибке выводится сообщение в строке состояния, а текущий цвет не меняется.
5. При успешной проверке значения передаются в `_apply_values(model, values)`.

HLS и CMYK допускают дробные значения при вводе; RGB задаётся целыми числами. В сообщении об ошибке указывается проблемный канал и допустимый диапазон.

### 4.2. Изменение ползунка

Tkinter вызывает `on_slider(model, index, raw_value)` при перемещении ползунка. Метод записывает новое значение в связанное поле, проверяет полный набор параметров этой модели и передаёт его в `_apply_values`.

Если ползунки программно передвигаются при синхронизации всех панелей, `updating` предотвращает повторное срабатывание обработчиков. Это важно, чтобы обновление интерфейса не запускало новый цикл преобразований.

Ползунки имеют целочисленный шаг. Для дробных значений HLS и CMYK можно воспользоваться полями ввода.

### 4.3. Выбор из палитры

Метод `choose_color(model)` открывает `colorchooser.askcolor`, передавая туда текущий RGB как начальное значение диалога. Если пользователь выбрал цвет, компоненты округляются до целых и синхронизируются через `_sync_from_rgb`. Отмена диалога оставляет состояние приложения без изменений.

Параметр `model` используется для заголовка диалога; сам диалог возвращает цвет в RGB, так как это представление служит внутренним.

### 4.4. Применение и синхронизация

Метод `_apply_values(model, values)` определяет исходную модель:

- CMYK переводится в RGB функцией `cmyk_to_rgb`;
- RGB используется непосредственно;
- HLS переводится в RGB функцией `hls_to_rgb`.

Затем `_sync_from_rgb(rgb, source_model, source_values)` устанавливает единое состояние. Метод вычисляет значения всех моделей из RGB. Для исходной модели он сохраняет введённые значения без обратного округлённого пересчёта. Так, если пользователь ввёл дробный HLS, исходные числа остаются в соответствующей панели, а две другие панели показывают представление получившегося RGB.

После этого обновляются поля, ползунки, цвет образца, HEX-код и строка статуса.

## 5. Преобразование цветовых моделей

### 5.1. Нормализация значений

В формулах удобно использовать компоненты в диапазоне от 0 до 1.

Для RGB:

\[
r = R/255,\quad g = G/255,\quad b = B/255
\]

Для процентов CMYK и HLS компоненты делятся на 100. Оттенок HLS задаётся в градусах от 0 до 360.

### 5.2. CMYK → RGB

Входные C, M, Y и K задаются процентами. Сначала каждая компонента нормализуется:

\[
c=C/100,\quad m=M/100,\quad y=Y/100,\quad k=K/100
\]

Затем компоненты RGB вычисляются по формулам:

\[
R=255(1-c)(1-k)
\]
\[
G=255(1-m)(1-k)
\]
\[
B=255(1-y)(1-k)
\]

Результат округляется до ближайшего целого, поскольку RGB в приложении отображается целыми каналами от 0 до 255.

Например, `C=0, M=100, Y=100, K=0` даёт красный цвет `(255, 0, 0)`.

### 5.3. RGB → CMYK

Компоненты RGB нормализуются делением на 255. Чёрная компонента определяется как:

\[
k=1-\max(r,g,b)
\]

Если `k = 1`, исходный цвет — чёрный. В этом особом случае функция возвращает `(0, 0, 0, 100)`, чтобы не делить на ноль.

Для остальных цветов:

\[
c=\frac{1-r-k}{1-k},\quad
m=\frac{1-g-k}{1-k},\quad
y=\frac{1-b-k}{1-k}
\]

Все четыре результата переводятся в проценты. В `rgb_to_cmyk` проценты округляются до двух знаков после запятой: это уменьшает потерю точности при обратном преобразовании.

### 5.4. HLS → RGB

HLS — это оттенок `H`, светлота `L` и насыщенность `S`. В программе `H` задаётся в градусах, а `L` и `S` — в процентах.

Перед расчётом оттенок приводится к круговому диапазону 0–360, а светлота и насыщенность нормализуются:

\[
h=H\bmod360,\quad l=L/100,\quad s=S/100
\]

Затем вычисляются насыщенность цветового диапазона (chroma), промежуточная компонента и сдвиг яркости:

\[
C=(1-|2l-1|)s
\]
\[
X=C\left(1-\left|\left(\frac{h}{60}\bmod2\right)-1\right|\right)
\]
\[
m=l-\frac{C}{2}
\]

Окружность оттенка делится на шесть секторов по 60 градусов. В зависимости от сектора пара `(C, X)` размещается в каналах RGB:

| Диапазон H | Временные компоненты `(R', G', B')` |
|---|---|
| 0–60 | `(C, X, 0)` |
| 60–120 | `(X, C, 0)` |
| 120–180 | `(0, C, X)` |
| 180–240 | `(0, X, C)` |
| 240–300 | `(X, 0, C)` |
| 300–360 | `(C, 0, X)` |

К каждой временной компоненте прибавляется `m`, результат умножается на 255 и округляется. Так получаются целочисленные каналы RGB.

При нулевой насыщенности `C` равен нулю, поэтому все три RGB-канала становятся одинаковыми: получается оттенок серого.

### 5.5. RGB → HLS

Сначала RGB нормализуется. Затем вычисляются максимальная, минимальная компоненты и их разность:

\[
M=\max(r,g,b),\quad m=\min(r,g,b),\quad \Delta=M-m
\]

Светлота:

\[
l=\frac{M+m}{2}
\]

Если `Δ = 0`, цвет ахроматический: оттенок и насыщенность принимаются равными нулю.

Если `Δ > 0`, насыщенность рассчитывается с учётом светлоты:

\[
s=\frac{\Delta}{M+m},\quad l\le0.5
\]
\[
s=\frac{\Delta}{2-M-m},\quad l>0.5
\]

Формула оттенка выбирается по каналу, равному максимуму:

\[
h'=((g-b)/\Delta)\bmod6,\quad M=r
\]
\[
h'=(b-r)/\Delta+2,\quad M=g
\]
\[
h'=(r-g)/\Delta+4,\quad M=b
\]
\[
H=60h'
\]

Результаты `H`, `L` и `S` переводятся соответственно в градусы и проценты. В коде светлота, насыщенность и оттенок округляются до двух десятичных знаков. Оттенок после округления приводится по модулю 360.

### 5.6. Точность и округление

RGB является дискретной моделью в приложении: его каналы — целые числа от 0 до 255. Поэтому при переводе дробных значений CMYK или HLS в RGB выполняется округление. Обратное преобразование может не восстановить исходные дробные параметры буквально, однако отображаемый цвет соответствует тому RGB, который был получен на первом шаге.

При тестировании обратные преобразования набора RGB-цветов через HLS и CMYK возвращали исходные значения без отклонения на проверенных данных. При произвольных входных значениях следует учитывать округление RGB до целых каналов.

## 6. Проверка вводимых данных

Проверка реализована в `_values_from_entries(model)`:

- пустое или нечисловое поле приводит к понятному сообщению;
- `NaN` и бесконечности отклоняются через `math.isfinite`;
- компоненты не должны выходить за заданные пределы;
- RGB-компоненты должны быть целыми;
- ошибка отображается в строке состояния, а не приводит к преобразованию некорректного значения.

Для HLS оттенок допускает ввод от 0 до 360. Внутри `hls_to_rgb` значение нормализуется оператором `% 360`, поэтому крайнее значение 360 соответствует оттенку 0.

## 7. Запуск приложения

Требуется Python с установленным Tkinter. Дополнительные пакеты не нужны.

```bash
python main.py
```

Вызов `root.mainloop()` запускает событийный цикл Tkinter, который принимает действия пользователя и вызывает соответствующие обработчики.

## 8. Схема потока данных

```text
Поле ввода / ползунок / диалог палитры
                    |
                    v
            Проверка значения
                    |
                    v
     CMYK или HLS --перевод--> RGB
        RGB -----------------> RGB
                    |
                    v
       Пересчёт всех представлений
          из общего состояния RGB
                    |
                    v
 Поля + ползунки + образец + HEX + статус
```

## 9. Итог

Архитектура разделяет вычисления и интерфейс: функции преобразования не зависят от Tkinter, а класс `ColorStudio` отвечает за события и отображение. Общее внутреннее представление RGB упрощает синхронизацию трёх моделей. Приложение использует только стандартную библиотеку Python, а формулы цветовых преобразований написаны непосредственно в исходном коде.
